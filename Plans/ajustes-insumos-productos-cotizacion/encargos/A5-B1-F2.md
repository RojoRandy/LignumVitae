## Estado actual — ya hecho, no lo rehagas

La API ya migró: los tipos de insumo y las unidades de medida son tablas con
CRUD. Endpoints ya funcionando y probados contra el servidor real:

- `GET /api/supply-types?limit=100` devuelve
  `{ data: { items: [{ id, slug, name, sortOrder, isSystem, isActive, createdAt, updatedAt }], total, page, limit, pages } }`
- `GET /api/units-of-measure?limit=100` igual, pero cada fila trae además
  `abbr` (por ejemplo `g`, `kg`, `ml`, `pz`, `pliegos`).
- `GET /api/supplies`: cada insumo ya NO trae `type` ni `unit` como texto. Trae
  `typeId`, `unitId` y además los objetos anidados
  `type: { id, slug, name, sortOrder, isSystem, isActive }` y
  `unit: { id, slug, name, abbr, sortOrder, isSystem, isActive }`.
- `POST` y `PATCH /api/supplies` esperan `typeId` y `unitId` (enteros), no los
  textos de antes.
- Lo mismo en las plantillas de insumos de velas, empaques y tarjetas: cada
  renglón lleva `unitId` al escribir y trae `unit` anidado al leer.
- `GET /api/supplies?type=WAX` sigue filtrando, ahora por slug.
- `packages/types/src/client/openapi-schema.d.ts` ya está regenerado.

Los catálogos ya vienen ordenados por `sortOrder` desde la API.
